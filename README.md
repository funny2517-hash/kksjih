# 둘의 지도 · 대한민국 커플 여행 기록

**설치 없이 확인:** [완성된 앱 ZIP 다운로드](https://github.com/funny2517-hash/kksjih/raw/refs/heads/main/downloads/our-korea.zip) → 압축 해제 → `index.html` 열기. [다운로드·게시 안내](downloads/README.md)

함께 다녀온 곳을 사진으로 채우는 PC 중심의 여행 지도 웹앱입니다. **실제 시·도 경계 17개 → 최종 시·군·구 경계 229개와 실제 좌표의 휴게소 128곳(원본 상·하행 210개)**를 포함합니다. 임의로 그린 지도나 가상의 휴게소 좌표를 사용하지 않습니다.

## 실행

Node.js **22.12 이상**(검증 환경: 24.19), npm이 필요합니다.

```sh
cd /workspace/kksjih  # 다른 환경에서는 프로젝트 디렉터리
npm ci
npm run dev
```

터미널에 표시된 주소를 브라우저에서 엽니다. 기본 포트는 5173입니다. 외부 지도 API 키, 계정, 데이터베이스 서버는 필요하지 않습니다. 지도·좌표 데이터와 JavaScript는 앱과 함께 제공되며 실행 중 외부 지도 API를 호출하지 않습니다.

```sh
npm run build       # dist/에 정적 배포 결과 생성
npm run preview     # 빌드 결과 확인 (기본 4173)
```

배포 시 `dist/` 전체를 HTTPS 정적 호스팅에 올리세요. 개발 서버는 개발용입니다. 루트 경로(`/`) 배포를 기준으로 합니다. **개발·미리보기·배포 주소는 서로 다른 저장소**입니다. 주소/포트/브라우저를 바꾸기 전에 백업하고 새 주소에서 복원하세요.

## 사용 방법

- **전국 여행**: 첫 화면에서는 17개 시·도만 보입니다. 시·도를 클릭하면 그 안의 시·군·구 지도로 전환됩니다. **전라남도 → 무안군, 서울특별시 → 광진구, 경기도 → 평택시**에서 탐색이 끝나고 사진을 등록합니다. 읍·면·동으로 더 들어가지 않습니다. 수원시처럼 일반시 안의 구가 나뉜 곳도 시 단위로 합칩니다. 위쪽 `대한민국`을 누르면 시·도 지도로 돌아갑니다. 검색·방문 필터는 현재 지도 단계 안에서 작동합니다.
- **사진 퍼즐**: 사진은 마지막 시·군·구 단계에서만 등록합니다. 시·도에서는 하위 지역 기록 수와 방문 색상을 보여주며 사진 등록 버튼을 표시하지 않습니다. 새로운 추억을 만들고 날짜, 제목, 메모, 사진을 저장합니다. 한 지역에 여러 방문을 남길 수 있고, 가장 최근의 사진 있는 기록의 첫 사진이 실제 지역 경계에 잘려 표시됩니다. 사진 없는 방문은 초록색 조각으로 표시됩니다. 기록 수정·삭제와 사진 크게 보기를 지원합니다. 예전 구 단위 기록·백업도 원래 코드를 별칭으로 유지해 해당 시에 모아 보여주며, 원본 기록은 자동 삭제하거나 덮어쓰지 않습니다.
- **휴게소**: 별도 탭에서 실제 좌표의 지점을 표시합니다. 같은 고속도로 노선·이름에 방향별 시설이 있으면 **네모 표시 하나**로 보여줍니다. 네모를 누르면 **상행·하행 탭**이 나오며, 각 탭에 사진과 메모를 따로 등록합니다. 단일 시설은 동그라미로 표시합니다. 원본 210개 지점을 지도에서는 128곳으로 표시하고, 기존 방향별 기록·백업은 원래 지점 ID에 해당하는 탭에 보존합니다. 이전 통합 모드에서 만든 기록도 저장된 지점 코드에 해당하는 방향으로 표시하며, 실제 방문 방향이 다르면 기록 수정의 **방문 방향** 선택에서 이동할 수 있습니다. 대표 위치는 해당 휴게소의 실제 원본 좌표 중 하나이며 임의로 만든 중간 좌표를 사용하지 않습니다. 이름 검색, 고속도로 번호 필터, 방문한 곳만 보기, 각 휴게소의 여러 사진·방문 기록을 지원합니다. 지점이 겹칠 때는 확대하거나 목록에서 선택하세요.
- **지도 조작**: 휠·트랙패드, 드래그, +/−, 전국 보기 버튼을 사용합니다. 최대 16배까지 확대할 수 있습니다. 지역명은 지도 확대 레이어 밖에 배치해 화면 기준 12px 크기를 유지합니다. 한글용 시스템 글꼴과 얇은 외곽선을 사용하고, 실제 글자 크기로 겹침을 검사합니다. 화면에서 겹치는 이름을 생략하고 확대에 따라 더 표시하며, 지역명 토글로 숨길 수 있습니다. 키보드로는 검색·목록·확대 버튼을 이용할 수 있습니다.
- **사진**: 기록당 최대 6장, 장당 12MB 이하 JPG/PNG/WebP입니다. 긴 변 최대 1600px JPEG(품질 82%)로 변환합니다. 원본 보관 도구가 아니므로 원본 사진은 따로 보관하세요.

## 저장·백업·복원

기록과 사진은 **IndexedDB**에 저장되어 브라우저를 닫고 같은 주소로 다시 열어도 유지됩니다. 기본 브라우저 모드는 서버 업로드가 없습니다. **GitHub 연결 시에는 사진과 기록을 저장소에 업로드**하며, 다른 기기의 변경을 새로고침으로 불러옵니다. 아래 GitHub 설정 안내를 참고하세요.

- **백업**: 오른쪽 위 `↓ 백업`으로 사진까지 포함한 JSON 파일을 저장합니다.
- **복원**: `↑ 복원`에서 JSON을 고르고 개수를 확인한 뒤 복원합니다. 기존 기록은 유지하고 같은 기록 ID는 백업 내용으로 덮어씁니다. 중복 복원으로 기록 수가 늘어나지 않습니다. 잘못된 형식·날짜·알 수 없는 장소·중복 ID는 전체를 거부하고, 브라우저 모드의 저장은 하나의 트랜잭션으로 처리합니다(GitHub 모드는 기록별 업로드). 복원 파일은 최대 150MB입니다.
- 파일 포맷은 `format: "our-korea-map"`, `version: 1`, `exportedAt`, `records`입니다. 각 기록은 `id`, `target`, `date`, `title`, `memo`, `photos`를 포함합니다.
- 브라우저 데이터 삭제, 시크릿 모드 종료, 브라우저의 저장소 정리 또는 기기 고장은 기록 소실을 일으킬 수 있습니다. 정기적으로 **별도 위치에 백업**하세요. 저장 공간 부족 시 오류를 표시합니다. 비밀 여행 사진이 담긴 백업 파일의 보관·공유에 유의하세요.

## 실제 데이터와 한계

### 행정경계

[South Korea Maps](https://github.com/southkorea/southkorea-maps)의 통계청(KOSTAT) 기반 **2018년 센서스 시·군·구 GeoJSON 250개**를 사용합니다. 원본을 mapshaper의 `weighted 8% keep-shapes`로 단순화하고 좌표 정밀도를 0.00001도로 맞췄습니다. D3 구면 렌더링에 맞게 링 방향을 정규화했습니다. 실제 좌표·섬·지역 식별 코드를 유지합니다. `scripts/build-hierarchy.mjs`가 이 경계들의 공유 선분을 사용해 실제 시·도 17개와 최종 시·군·구 229개를 합성합니다. 일반시의 구는 시 경계로 합치고 광역시의 구·군은 유지합니다. 별도 읍면동 경계나 임의의 도형은 사용하지 않습니다.

**현재 법정 행정구역의 최신 지도는 아닙니다.** 이후의 명칭·관할 변경(예: 군위군 대구 편입, 특별자치도 개칭 등)은 반영하지 않습니다. 화면의 시·도명도 경계의 2018년 기준으로 표시합니다. 원본의 미세 경계 교차·단순화 오차가 있어 측량·경계 판정 용도로 사용할 수 없습니다. 제주·울릉도에 더해 원본에서 빠진 독도 동·서도는 별도의 실제 2018년 SGIS 경계로 보완합니다. 좌표를 이동시키거나 삽입지도 형태로 재배치하지 않습니다.

### 독도 보완과 위치 검증

기존 South Korea Maps의 울릉군에는 울릉도만 포함되어 독도가 누락돼 있었습니다. [vuski/admdongkor의 2018-07-24 행정동 자료](https://github.com/vuski/admdongkor/blob/dd1881663fcabc69b81393604e91ebf3a4202e9a/ver20180724/HangJeongDong_ver20180724.geojson)에서 **울릉읍(3743011)의 동도·서도 두 폴리곤만 원래 좌표 그대로 추출**해 울릉군(37430)에 붙이고, 경상북도 경계에도 반영합니다. 별도의 가짜 행정구역을 만들지 않으며 지역 수와 기존 기록 ID는 유지됩니다.

- GeoJSON 순서인 **경도, 위도**를 유지하며, 동·서도 경계 범위는 동경 131.8632~131.8713°, 북위 37.2383~37.2443°입니다.
- 동도 기준점(북위 37°14′26.8″, 동경 131°52′10.4″)과 서도 기준점(북위 37°14′30.6″, 동경 131°51′54.6″)이 각각 실제 폴리곤 내부에 포함되는지 검사합니다. [외교부 독도 개관 참고](https://dokdo.mofa.go.kr/kor/introduce/outline.jsp).
- 기존 울릉도 해안 꼭짓점과 독도 해안 꼭짓점 간 최소 거리는 이 데이터에서 약 **87.64km**입니다. 단순화된 경계의 표본 꼭짓점 간 계산이며, 기준 지점을 달리한 공식 거리 표기와 같은 수치라고 주장하지 않습니다. 독도가 울릉도의 남동쪽에 놓이는지도 검사합니다.
- 본토·울릉도·독도에 **같은 Mercator 투영**을 적용합니다. 전국·경북 지도의 자동 범위에도 독도를 포함합니다. 작은 점과 연결선은 위치를 읽기 위한 표식이며 섬의 실제 경계 크기·좌표를 바꾸지 않습니다. 독도·울릉도의 이름이나 점, 또는 오른쪽 위 바로가기 버튼을 한 번 누르면 해당 섬 이름의 기록창이 바로 열립니다. 첫 클릭이 경북 지도 전환에서만 끝나지 않으며, 경상북도·울릉군 맥락을 함께 표시합니다. 행정구역 단위 기록은 기존처럼 울릉군에 저장하며, 새 기록 제목에는 선택한 섬 이름을 기본 입력합니다. 이름·점의 마우스 클릭과 태블릿 터치, 기본 제목, 미저장 내용 보호를 검증합니다.
- 원본 커밋·SHA-256·추출 절차는 `public/data/sources.json`에 있습니다. 원본 33MB 파일은 선택적 재가공 시에만 내려받으며, 실행용 파일에는 추출한 작은 경계 데이터가 포함됩니다.

**출처·라이선스:** 본 데이터는 통계청 통계지리정보서비스(SGIS, https://sgis.kostat.go.kr)에서 공공누리 제1유형으로 개방한 행정동 경계를 가공한 것이며(가공: vuski/admdongkor, https://github.com/vuski/admdongkor), CC BY 4.0으로 배포됩니다. 이 앱에서는 동·서도를 추출하고 링 방향만 D3에 맞게 정규화했으며 단순화·이동하지 않았습니다. [원본 데이터 이용 조건](public/data/DOKDO-LICENSE.txt)을 보존합니다.

재현: `python scripts/prepare-dokdo.py` (고정 URL 다운로드 → SHA-256 검증 → 동·서도 추출 → 상위 경계 재생성). GitHub의 고정 원본을 실제로 다시 내려받아 해시 일치와 가공 결과의 재현성도 확인했습니다.

### 휴게소 위치

공개 저장소 [kmj381900-debug/rest_area_main](https://github.com/kmj381900-debug/rest_area_main)의 `rest_areas.db`에 담긴 **210개 실제 휴게소 위치 스냅샷**에서 이름, 노선 번호, 방향, 위도·경도만 추출했습니다. 예: 평창(인천) 37.610876, 128.463363 / 하남드림 37.530281, 127.206084. 좌표를 추측하거나 지명에서 임의 배치하지 않았습니다.

**한국도로공사 실시간 공식 API에 직접 연결한 데이터는 아닙니다.** 방향과 목적지 이름도 원본 값을 유지합니다. 부안고려청자처럼 원본의 상·하행 표기가 중복된 경우는 탭에 표시한 목적지로 구별하며, 임의로 방향을 바꾸지 않습니다. 원본의 최초 조사일과 전체 포괄성은 명시되어 있지 않으며, 신규·폐쇄·민자 휴게소 누락 및 위치 오차가 있을 수 있습니다. 전국 모든 휴게소의 최신 목록을 보장하지 않습니다. 다른 앱의 코드·API 키·인증 정보는 가져오지 않았습니다. 상용 재배포 전에는 원출처의 이용 조건을 확인하세요.

정확한 원본 URL, 고정 커밋, SHA-256, 가공 방법은 [public/data/sources.json](public/data/sources.json)에 기록되어 있습니다. 포함된 정적 데이터 덕분에 앱 실행에는 원본 사이트 연결이 필요 없습니다.

선택 사항으로 원본 재다운로드·검증·가공을 재현하려면 Python 3.10+와 설치된 npm 의존성이 필요합니다.

```sh
python scripts/prepare-data.py
```

원본 체크섬이 다르면 중단합니다. 원본에 기반한 일부 미세 경계 교차에 대해 mapshaper가 경고할 수 있습니다. 데이터 교체 시 기존 기록의 `region-행정코드`, `rest-ID`가 다른 장소로 바뀌지 않도록 매핑·마이그레이션이 필요합니다.

## 테스트

```sh
npm test                 # 데이터 무결성, 백업 검증, 날짜·사진·대상 검증, 정렬
npm run test:e2e         # 실제 Chromium 기능 테스트
npm run build
```

E2E는 `/usr/bin/chromium`이 있으면 사용하며, 다른 브라우저 경로는 `CHROMIUM_PATH`로 지정합니다. 시스템 Chromium이 없으면 먼저 Playwright 브라우저를 설치하세요.

```sh
npx playwright install chromium
npm run test:e2e
```

## 구성

Vite + JavaScript, D3(실제 GeoJSON 투영·SVG·확대/축소), idb(IndexedDB)로 구현했습니다. `src/main.js`는 UI·지도, `src/records.js`는 백업/기록 검증, `src/storage.js`는 영속 저장, `src/photo.js`는 사진 축소를 담당합니다. 개발 기준은 PC 화면이며 작은 화면에서는 기록 패널이 지도 아래로 이동합니다.

## 설치 없이 파일로 확인하기

`npm run build:standalone`으로 만든 `dist/our-korea.html`에는 JavaScript, CSS와 실제 지도 데이터가 모두 포함됩니다. PC에서 내려받아 Chrome/Edge로 열어볼 수 있습니다. 관리형 브라우저가 파일 열기를 차단하면 정적 서버로 제공하세요. 파일을 다른 위치로 옮기거나 실행 주소를 바꾸기 전에는 기록을 백업하세요.

### 저장 버튼이 반응하지 않는 것처럼 보일 때

사진 처리 중에는 `사진 처리 중…`과 처리 장수를, 저장 중에는 `저장 중…`을 표시합니다. 사진 처리가 끝나야 저장할 수 있습니다. 날짜·사진·저장 공간 오류는 버튼 위에 계속 표시되며, 실패해도 입력 내용과 사진을 유지합니다. 저장 트랜잭션이 12초 이상 응답하지 않으면 취소를 시도하고 재시도할 수 있게 합니다. 브라우저가 완료 상태를 전달하지 않아 취소 여부가 불확실할 때는 완료 여부 미확인으로 표시하며, 같은 기록 ID로 재시도하므로 중복 방문이 생기지 않습니다. 저장 후 전체 사진 DB를 다시 읽는 작업도 제거했습니다.

검증에는 1600×1200 사진 6장 저장·재접속, 저장 공간 부족을 강제로 일으킨 뒤 작성 내용 유지 및 재시도, 비어 있는 날짜 오류 표시, 응답 없는 저장 요청의 시간 제한과 취소가 포함됩니다.

### 휴게소 지도의 고속도로 선

휴게소 탭에는 실제 도로 형상을 얇은 회녹색 선으로 표시합니다. 전국 화면에서는 도로명을 겹쳐 쓰지 않고, 휴게소를 선택하면 같은 노선의 시설을 선명하게 유지하고 다른 노선 시설을 옅게 표시합니다. 상·하행 네모 표식과 방향별 사진 등록은 그대로입니다. 지도 상단의 **고속도로** 체크를 끄면 선을 숨길 수 있습니다.

선의 출처는 [Natural Earth 1:10m roads](https://github.com/nvkelso/natural-earth-vector)이며 퍼블릭 도메인입니다. 원본의 `expressway=1` 실제 선을 추출했으며 휴게소를 직선으로 이어 만든 지도가 아닙니다. **과거의 개략 데이터**이므로 최신 개통 도로, 램프, 세밀한 굴곡이 누락될 수 있고 휴게소 좌표와 약간 어긋날 수 있습니다. 길찾기용으로 사용하지 마세요. 노선 번호가 없는 데이터라 노선 필터는 휴게소에만 적용하며 도로 선은 전체 맥락으로 유지합니다.

원본 커밋과 SHA-256은 `public/data/sources.json`에 보존합니다. 해당 원본을 내려받은 뒤 `node scripts/prepare-highways.mjs /원본/경로.geojson`으로 같은 선 데이터를 재생성할 수 있습니다. 실행 시에는 가공된 작은 GeoJSON이 앱에 포함되어 외부 지도 요청이 필요 없습니다.

## GitHub Pages 게시와 사진 직접 업로드

**Google Drive 연결은 사용하지 않습니다.** GitHub Pages에서 사이트를 열고, 앱의 **☁ GitHub 연결**로 사진과 메모를 저장소에 직접 올립니다. 서버나 Google 설정은 필요하지 않습니다. 사이트용 저장소와 사진용 저장소를 다르게 지정할 수도 있습니다.

### 이미 설정한 GitHub Pages 사용

`Settings → Pages`의 기존 Source를 바꾸지 않아도 되도록 다음 형태를 지원합니다.

- **Deploy from a branch · main · /(root)**: 루트 페이지가 완성본 `downloads/index.html`로 이동합니다. 원본 JS를 브라우저에서 그대로 실행하지 않습니다. 루트의 `_config.yml`은 사진용 `travel-data`를 Pages 빌드에서 제외합니다.
- **Deploy from a branch · main · /docs**: 완성본 `docs/index.html`이 바로 실행됩니다. 두 완성본은 같은 파일로 갱신합니다.
- **GitHub Actions**: `.github/workflows/pages.yml`이 빌드한 단일 HTML만 Pages에 배포합니다. 워크플로는 기존 Pages Source를 조회해 Actions 방식일 때만 배포하고, 브랜치 방식의 기존 설정은 바꾸지 않습니다. 사진 업로드(`travel-data/**`)만 바뀐 경우에는 이 워크플로를 실행하지 않습니다.

기본 주소는 `https://funny2517-hash.github.io/kksjih/` 형식입니다. **정확한 게시 주소와 배포 결과는 Settings → Pages의 “Visit site”에서 확인**하세요. 커스텀 도메인을 설정했다면 그 주소를 사용합니다. 로컬 기능은 경로와 상관없이 같은 원본의 IndexedDB를 쓰며, 다른 도메인에서 가져온 기록은 백업/복원이 필요합니다.

GitHub Pages는 정적 사이트이므로 사진을 저장하려면 아래 토큰 연결이 필요합니다. GitHub 로그인 쿠키만으로 앱에서 파일을 쓸 수는 없습니다. 이 앱은 **GitHub personal access token을 메모리에만** 보관하며 사이트 소스·localStorage·백업 파일에 포함하지 않습니다.

### 1. 사진 저장소와 토큰 준비

1. **비공개 사진은 Pages를 켜지 않은 별도 비공개 저장소**를 권장합니다. 예를 들어 `내아이디/couple-memories`를 만들고 README를 추가해 `main` 브랜치가 존재하도록 하세요. 현재 사이트 저장소를 사용할 수도 있지만, **공개 저장소의 사진과 메모는 모두 공개**됩니다. GitHub Pages가 공개되는 것과 저장소가 비공개인 것은 별개이므로 사이트와 사진 저장소를 분리하는 편이 명확합니다.
2. GitHub 우측 프로필 → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**으로 이동합니다. 바로가기: https://github.com/settings/personal-access-tokens/new
3. Resource owner를 고르고 **Only select repositories**에서 사진을 저장할 저장소 **하나만** 선택하세요. 만료일을 정하세요.
4. **Repository permissions → Contents → Read and write**를 선택하고 발급합니다. Metadata 읽기는 기본입니다. Actions·Workflows·관리자 권한은 앱 사진 업로드에 필요하지 않습니다. 보호된 브랜치는 직접 쓰기가 차단될 수 있으므로 사진용 저장소의 일반 브랜치를 사용하세요.
5. 토큰을 앱 연결 창에 직접 입력합니다. **채팅·README·소스 코드·GitHub Secrets에 토큰을 붙여넣지 마세요.** 앱을 공개한다고 토큰을 공개할 필요는 없습니다.

두 사람이 각각 업로드하려면 저장소 쓰기 권한이 필요합니다. **개인 계정 소유 저장소의 외부 협업자는 fine-grained PAT 지원에 제한이 있습니다.** 두 사람이 멤버인 조직의 저장소를 사용하면 조직 대상 fine-grained 토큰을 각각 만들 수 있으며 조직 승인 정책이 적용될 수 있습니다. 개인 저장소 외부 협업자는 classic PAT를 사용할 수 있지만, 비공개 저장소에는 `repo` 범위가 필요하고 접근 가능한 다른 저장소까지 권한이 넓어집니다. 권한 범위를 이해한 뒤 선택하세요. 공개 저장소 전용 classic 토큰은 `public_repo` 범위입니다. **상대방과 토큰을 공유하는 방식은 권장하지 않습니다.**

### 2. 앱 연결과 사진 등록

1. 게시한 사이트에서 **☁ GitHub 연결**을 누릅니다.
2. 저장소(`소유자/저장소`), 브랜치(`main`), 전용 토큰을 입력하고 **저장소 연결**을 누릅니다. 공개 저장소는 사진·메모 공개 동의를 체크해야 연결됩니다.
3. 이전처럼 시·군·구 또는 휴게소 방향을 선택하고 사진과 메모를 저장합니다. 사진은 긴 변 1600px로 줄인 뒤 **`travel-data/photos/`의 이미지 파일**로 업로드되고, 기록은 **`travel-data/records/`의 JSON 파일**로 추가됩니다. 빈 폴더를 미리 만들 필요는 없습니다.
4. 상대방도 같은 저장소와 브랜치를 각자의 토큰으로 연결하세요. **↻ 새로고침**으로 상대방이 올린 기록을 가져옵니다. 실시간 자동 동기화는 아닙니다.
5. 이전 브라우저 기록은 연결 창의 **이 브라우저 기록을 GitHub로 복사**로 옮깁니다. 브라우저 원본은 보존하며 같은 ID는 건너뜁니다. 다른 주소에 저장된 기록은 그 주소에서 먼저 백업 → 현재 사이트의 브라우저 모드에서 복원 → GitHub 연결 → 복사하세요.

### 보관·실패·한계

- 토큰은 **현재 사이트 탭의 메모리에만** 있습니다. 페이지 새로고침·탭 종료 후 다시 입력해야 합니다. 저장소 이름·브랜치·공개 여부·모드만 기억합니다. 연결 만료/실패 시 로컬 저장으로 조용히 전환하지 않으며, **연결 해제 · 브라우저 저장으로 전환**으로 명시적으로 바꿀 수 있습니다. 연결 해제는 토큰의 메모리 참조를 버릴 뿐 GitHub에서 토큰 자체를 폐기하지 않습니다. 필요하면 GitHub 설정에서 폐기하세요.
- 사진 업로드 후 기록 수정본을 추가하므로 중간 실패한 사진은 미참조 파일로 남을 수 있습니다. 같은 사진은 SHA-256 경로로 재사용합니다. 다른 저장 작업과 HEAD 변경이 겹치면 같은 파일 경로로 제한된 재시도를 하며, 응답 유실 시 Git blob SHA로 이미 저장됐는지 확인합니다.
- 공유 JSON 하나를 덮어쓰지 않고 **수정본을 새 파일로 추가**합니다. 같은 기록을 동시에 수정하면 추가 사본에 **[동시 수정본]**을 표시해 둘 다 남깁니다. 클라이언트 시계 순서로 상대방의 수정을 버리지 않습니다.
- **지도에서 삭제해도 과거 사진·수정본·Git 커밋 이력은 남습니다.** 저장 용량은 누적됩니다. GitHub에서 파일만 삭제해도 과거 커밋에서 복구할 수 있으므로 민감한 파일의 완전 삭제는 별도의 Git 이력 정리가 필요합니다. 앱 전용 `travel-data` 파일을 직접 편집·이동·삭제하면 불러오기가 실패할 수 있습니다.
- GitHub는 무제한 사진 보관 서비스가 아닙니다. 저장소 크기·API 요청·GitHub Pages 전송량과 이용 정책의 제한을 받습니다. 많은 사진과 수정본은 저장소와 초기 로딩을 무겁게 합니다. 사진을 대량으로 장기간 보관하려면 사진 전용 저장소 서비스를 검토하세요.
- 비공개 저장소 사진은 인증된 GitHub API 응답으로 읽으며 공개 다운로드 URL에 토큰을 붙이지 않습니다. 단, 다른 도구로 같은 저장소를 Pages/호스팅에 통째로 게시하면 파일이 노출될 수 있습니다. 비공개 사진용 저장소의 Pages는 끄고 별도 사이트에서 연결하세요.
- **↓ 백업**은 현재 연결한 저장소의 사진까지 기존 JSON 포맷으로 내보냅니다. 연결하지 않은 브라우저 모드에서도 복원할 수 있습니다. GitHub 복원/기존 기록 복사는 기록별로 진행하므로 중간 실패하면 일부만 업로드됐을 수 있습니다. 입력 내용은 유지되며 새로고침으로 완료 여부를 확인한 뒤 재시도하세요.
- 현재 기록의 사진은 퍼즐 표시를 위해 브라우저 메모리로 읽습니다. 수천 장 규모에서는 초기 로딩과 메모리 사용량이 커질 수 있습니다. API는 `https://api.github.com`에만 연결하며 브라우저 CORS 요청에서 토큰을 Authorization 헤더로 보냅니다.
- 테스트는 가짜 GitHub HTTP 응답으로 실제 앱의 이미지 업로드·공유 조회·충돌 보존·오류 복구·토큰 비저장을 검증합니다. **실제 계정의 토큰·권한·보호 규칙과 라이브 Pages 주소는 해당 계정 설정으로 별도 확인해야 합니다.**

### 완성본 재생성

```sh
npm run build:standalone
node scripts/package-downloads.mjs
```

그 뒤 `downloads/index.html` 하나를 ZIP으로 묶어 `downloads/our-korea.zip`을 갱신합니다. `docs/index.html`은 `downloads/index.html`과 동일해야 합니다. GitHub Actions는 소스에서 새 완성본을 빌드합니다.
